# ۱. تحلیل فاصله با فرقهٔ فعلی

## ۱.۱ چه چیزی امروز هست

| مکانیک | رفتار PHP/اسپرینت |
|--------|-------------------|
| دعوت شب فرقه | `CheckCult` + شانس `CultAttemp` / شاخه‌های ویژه؛ موفقیت → `ConvertPlayer` به `role_ferqe` **فوری** |
| گاز گرگ/ومپ | فلگ معوق تا `BittanCheck` در مرز رأی→شب |
| رویس | مرگ → انتخاب دوم تبدیل در شب بعد |
| شکارچی (`role_shekar`) | قبل از فرقه در شب؛ کشت قطعی `role_ferqe` / `role_Royce`؛ PV قربانی `HunterKilledCultistOn` (عبادت + شمشیر) |
| دیان | علامت روز۲ با مهلت ۴روزه برای برد سیاه — الگوی «مارک + رویداد بعدی» نزدیک‌ترین خویشاوند مفهومی است |
| اعدام | بیشینهٔ یکتا در `CheckVote`؛ استثناها قبل از مرگ (شاهزاده، شوالیه سیاه، منافق، کلانتر) |

## ۱.۲ چه چیزی این نقش اضافه می‌کند

دارنشان تبدیل شبانه با شانس نیست. **علامت شب → شرط اعدام روز بعد → انتخاب PV فوری برای تبدیل قطعی نفر سوم** است. اعدام‌شده می‌میرد؛ عضو جدید زنده می‌ماند. اگر اعدام روی علامت نخورَد، علامت می‌سوزد.

فایدهٔ برد: هر اعدام درست = یک عضو قطعی جدید → نزدیک‌تر به غلبهٔ عددی `ferqeTeem` (اسپرینت ۴).

## ۱.۳ برخورد / هم‌پوشانی

| مقایسه | نتیجه |
|--------|--------|
| در برابر `CheckCult` | کانال جذب موازی؛ می‌تواند همان شب دعوت معمولی + علامت دارنشان هم‌زمان باشد |
| در برابر گاز معوق | تبدیل دارنشان **فوری در فاز رأی** است؛ گاز تا شب بعد معوق می‌ماند → ریسک race (بخش ۱۱) |
| در برابر منافق اعدام‌شده | برد مستقیم `monafeq` بازی را می‌بندد؛ تبدیل نباید بعد از `GamedEnd` اجرا شود |
| در برابر شکارچی | مرگ شبانهٔ خودِ دارنشان باید PV اختصاصی کاربر را بگیرد، نه لزوماً متن عبادت `HunterKilledCultistOn` |

# ۳. رفتار هدف — خلاصه یک‌صفحه‌ای

1. هر شب واجد شرایط، یکی از زنده‌های **خارج از فرقه** را علامت می‌زند.  
2. علامت تا پایان فاز رأیِ «فردا» زنده می‌ماند مگر بسوزد/باطل شود.  
3. اگر همان علامت‌خورده **واقعاً اعدام و کشته شود**، تایمر/فاز رأی برای انتخاب PV دارنشان وقفه می‌خورد (الگوی کلانتر/رویس).  
4. دارنشان یک زندهٔ غیرفرقهٔ دیگر را برمی‌گزیند → `ConvertPlayer` قطعی به `role_ferqe` + پیام‌ها.  
5. اعدام‌شده مرده می‌ماند؛ عضو جدید زنده است و از شب بعد در مسیر فرقه قرار می‌گیرد (`SendNight` / تیم).  
6. اگر علامت‌خورده اعدام نشود (تساوی، صلح، نجات شاهزاده/سپر سیاه، هدف اشتباه، …) → علامت می‌سوزد؛ PV سوخت به دارنشان.

# ۴. اکشن شب — UI / فیلتر / ذخیره

## ۴.۱ گیت‌های ارسال کیبورد

همان گیت‌های مشترک `SendNightRole` (اسپرینت ۵الف §۴): قبلاً در `SendNight`؛ `NotSend_{role}`؛ یخ شب قبل؛ زندانی شاهدخت؛ `NotSendNight` / `NotSend:{uid}`.

| مورد | مقدار |
|------|--------|
| متن پرس | `AskDarNeshanMark` — پیشنهاد: «امشب نشان قربانی رو روی کی می‌ذاری؟» (+ اختیاری `DiscussWith` اگر هم‌تیمی نام‌دار) |
| callback | `NightSelect_DarNeshan` |
| skip | بله (مثل اکثر نقش‌های شب) — skip = بدون علامت آن شب |
| ذخیره | `Selected:{uid}` = هدف؛ سپس در resolve شب (یا بلافاصله پس از تأیید انتخاب — ترجیح: در resolve شب مثل بقیه) ست مارک |

## ۴.۲ فیلتر کیبورد هدف علامت

| شرط | اثر |
|-----|-----|
| زنده | الزامی |
| خود دارنشان | حذف |
| اعضای `ferqeTeem` (فرقه، رویس، مومیایی، فرانک، و خود دارنشان‌های دیگر) | حذف |
| سطل عملیاتی ferqe | حذف (هم‌پوشان با بالا اگر سیاست §۲ پذیرفته شود) |
| `role_BrideTheDead` | پیشنهاد: حذف از هدف (هم‌الگوی رأی) — **assumed** |
| زندانی شاهدخت به‌عنوان هدف | **پیشنهاد: مجاز برای علامت** (مارک بازدید نیست) — شکاف G3 |
| هدف یخ‌زده | مجاز (یخ اکشن هدف را می‌بندد نه علامت‌پذیری) |

## ۴.۳ ماهیت بازدید

**پیشنهاد قفل‌شدهٔ طراحی (تا خلاف آن تصمیم شود):** علامت = **غیر‌بازدید**.

- `UserInHome` برای دارنشان ست نشود.  
- تله هانتسمن، فرشته، فاحشه، قاتل‌خانگی، … تریگر نشوند.  
- شبیه مارک دیان، نه دعوت `CheckCult`.

اگر محصول بخواهد «خواندن قربانی از نزدیک» فلور داشته باشد، باید صریحاً به بازدید تبدیل شود (شکاف G4).

## ۴.۴ Resolve شب علامت

پس از تأیید انتخاب معتبر در پایان شب (اسلات پیشنهادی: **بعد از `CheckCult`** یا هم‌زمان با نقش‌های غیرتهاجمی — شکاف G5 ترتیب دقیق):

1. پاک مارک قبلی همان بازیکن/سشن اگر هنوز مانده (نباید دو مارک فعال از یک دارنشان بماند).  
2. ست:
   - `DarNeshanMarkTarget` = uid هدف (یا `DarNeshanMark:{markerUid}=targetUid`)  
   - `DarNeshanMarkBy` = uid دارنشان  
   - `DarNeshanMarkNight` = `Night_no` فعلی  
3. PV به دارنشان: `DarNeshanMarkSet` — «نشان قربانی رو زدی به {0}.»  
4. به هدف / گروه: **سکوت** (پیشنهاد پیش‌فرض؛ افشا علامت قدرت را می‌کشد — شکاف G6 اگر بخواهند تییز گروهی).

اگر چند دارنشان در یک دست (معمولاً نباید): هر کدام یک مارک مستقل؛ اعدام یک هدف فقط مارک(های) منطبق را شعله‌ور می‌کند — **assumed**.

# ۵. پایداری مارک و سوخت

## ۵.۱ کلیدهای State (مفهومی)

| کلید | معنی |
|------|------|
| `DarNeshanMarkTarget` | uid علامت‌خوردهٔ فعال (سراسری اگر حداکثر یک نقش؛ یا per-marker) |
| `DarNeshanMarkBy` | uid دارنشان صاحب مارک |
| `DarNeshanMarkNight` | شبی که مارک گذاشته شد |
| `DarNeshanPickPending` | وقفهٔ انتخاب پس از اعدام فعال است |
| `DarNeshanPickDeadline` | زمان انقضای PV دوم |
| `NotSend` / صف کیبورد pick | مشابه `HunterKill` / `RoyceSelectd2` |

## ۵.۲ عمر مارک

- معتبر برای **اولین فاز رأی کامل بعد از شبی که مارک ست شده** (یعنی «فردا» در چرخهٔ شب→روز→رأی).  
- پس از آن فاز رأی (چه اعدام شده چه نه، مگر تبدیل موفق در جریان): مارک پاک می‌شود.

## ۵.۳ سوخت / باطل بدون تبدیل

| رویداد | اثر | پیام |
|--------|------|------|
| فاز رأی تمام شد و علامت‌خورده اعدام/کشته نشد | Del مارک | `DarNeshanMarkBurned`: «صبح شد و {0} اعدام نشد. علامت سوخت.» |
| صلح (`GroupInSolh`) در آن رأی | بدون اعدام → سوخت | همان |
| تساوی / بدون رأی / `no_kill` | سوخت | همان |
| نجات شاهزاده بار اول / سپر شوالیه سیاه (بدون مرگ) | سوخت (چون «اعدام منجر به مرگ» رخ نداد) | همان یا پیام اختصاصی اختیاری |
| مرگ شبانهٔ علامت‌خورده قبل از رأی | Del مارک؛ بدون تبدیل | پیشنهاد: `DarNeshanMarkTargetDead` (متن پیشنهادی §۹) |
| مرگ / ترک بازی دارنشان قبل از شعله | Del مارک | پیشنهاد: بی‌صدا یا PV تیم — شکاف G7 |
| خودکشی/AFK علامت‌خورده در شب بعد از مارک | مثل مرگ شبانه | سوخت |
| تبدیل شبانهٔ علامت‌خورده به فرقه قبل از رأی (`CheckCult`) | مارک بی‌معنی → Del | پیشنهاد سوخت خاموش یا «دیگه بیرون فرقه نیست» |

# ۶. هوک اعدام / روز — زمان‌بندی دقیق

## ۶.۱ نقطهٔ اتصال پیشنهادی در `CheckVote`

پس از شاخه‌هایی که **مرگ را متوقف می‌کنند** (شاهزاده بار اول، شوالیه سیاه با سپر، صلح، تساوی)، و **قبل از** ادامهٔ عادی به شب:

ترتیب پیشنهادی وقتی برنده یکتاست و قرار است بمیرد:

1. استثناهای نجات (الف/ب اسپرینت ۸) — اگر return بدون مرگ → مسیر سوخت مارک در پایان فاز.  
2. منافق → `GamedEnd('monafeq')` و **قطع کامل**؛ اگر منافق همان علامت‌خورده بود → تبدیل دارنشان **اجرا نشود** (بازی تمام است).  
3. متن اعدام (`killed_user` / `RulerKillPl`).  
4. کلانتر → مسیر `HunterKill` موجود؛ اگر کلانتر علامت‌خورده است: اول تیر مرگ کلانتر؟ **شکاف G8** — پیشنهاد: مارک فقط وقتی `UserDead(..., vote)` برای علامت‌خورده واقعاً ثبت شد؛ اگر کلانتر اعدام شود، پس از مرگ کلانتر (نه تیر ثانویه) اگر او مارک بوده شعله بزند.  
5. مرگ عادی علامت‌خورده: `UserDead(..., vote)` سپس اگر `uid == DarNeshanMarkTarget` و `DarNeshanMarkBy` زنده و نقشش هنوز `role_DarNeshan` (یا فرقهٔ تبدیل‌نشده از این نقش — معمولاً همان):  
   - ست `DarNeshanPickPending`  
   - تمدید تایمر (پیشنهاد **+۴۰ تا ۴۵ث** هم‌تراز کلانتر)  
   - **بدون** رفتن به `TroubleVote` / `BittanCheck` / شب تا resolve پیک  
   - PV `DarNeshanPickAsk`: «{0} اعدام شد. کی رو همین حالا بیاری تو فرقه؟» + کیبورد

## ۶.۲ فیلتر کیبورد پیک دوم

| شرط | اثر |
|-----|-----|
| زنده | الزامی |
| غیر فرقه (`ferqeTeem` / سطل ferqe) | الزامی |
| ≠ اعدام‌شده | الزامی (مرده است) |
| ≠ خود دارنشان | الزامی |
| هدفی که همین الان با گاز/نقش دیگر «در صف تبدیل» است | **شکاف G9** — پیشنهاد: مجاز، ولی Convert قطعی فرقه گاز را باطل کند |

## ۶.۳ موفقیت پیک

1. `ConvertPlayer(target → role_ferqe)` قطعی (دور زدن `CultAttemp`).  
2. PV عضو جدید: `DarNeshanConvertYou` — متن کاربر.  
3. PV/تیم فرقه: `DarNeshanCultJoin` — متن کاربر.  
4. `rpush SendNight` / هم‌تیمی‌ها مثل `CultJoin`.  
5. پاک `DarNeshanPickPending` + مارک.  
6. اعلام گروهی: **پیشنهاد پیش‌فرض سکوت** (فقط PV/تیم) تا با اعدام قاطی نشود — شکاف G10.  
7. سپس ادامهٔ پس‌فاز رأی (دردسرساز / بیتن / شب) مگر `CheckEndGame` الان فرقه را برنده کند.

## ۶.۴ تایم‌اوت / بدون هدف معتبر / مرگ قبل از پیک

| حالت | رفتار پیشنهادی |
|------|----------------|
| تایم‌اوت بدون انتخاب | تبدیل نمی‌شود؛ مارک پاک؛ PV `DarNeshanPickTimeout`؛ بازی ادامه |
| skip اگر در کیبورد باشد | همان تایم‌اوت |
| هیچ هدف معتبری روی کیبورد نیست | خودکار شکست + `DarNeshanPickNoTarget` |
| مرگ دارنشان وسط وقفه (نادر؛ مگر killgame/ترک) | شکست تبدیل؛ مارک پاک |
| ترک بازی / لیو علامت‌زن | شکست |
| دردسرساز: اعدام دور اول مارک را شعله کرد | پیک باید **قبل از** TroubleVote تمام شود یا Trouble به بعد از پیک موکول شود — **شکاف G11 اجباری** |

# ۷. ماتریس تعاملات

راهنما: **known** = از اسناد موجود + منطق پیشنهادی صریح این spec؛ **assumed** = پیشنهاد معقول بدون تأیید کاربر؛ **gap** = نیاز تصمیم.

| طرف مقابل | رفتار | وضعیت |
|-----------|--------|--------|
| شکارچی (`role_shekar`) شب روی دارنشان | کشت مثل فرقه/رویس؛ PV مرگ به دارنشان = متن کاربر (`DarNeshanKilledByShekar`) به‌جای `HunterKilledCultistOn`؛ گروه می‌تواند `HunterKilledCultist` بماند یا کلید جدید | known + پیام جدید |
| شکارچی روی عضو تبدیل‌شدهٔ جدید | پس از تبدیل = `role_ferqe` → مسیر عادی شکار | known |
| کلانتر (پیام‌های «Hunter*» رأی) | قاتل مرگ شب نیست؛ متن کاربر «شکارچی…علامت‌ها» برای کلانتر **نباید** استفاده شود | known (تمایز نقش) |

### مرگ PV و شکارچی — تحلیل

- در PHP، قربانی فرقه/رویس از شکارچی `HunterKilledCultistOn` می‌گیرد (عبادت + شمشیر).  
- متن کاربر برای دارنشان («از روی دستت علامت‌ها رو خوند») **فلور نقش‌محور** است و با کلید فعلی یکی نیست → کلید جدید الزامی.  
- «شکارچی» در متن‌های بازی گاهی کلانتر را هم در نام کلید می‌پوشاند (`HunterLynchedChoice`)؛ برای این مرگ فقط **`role_shekar`** مدنظر است.  
- سایر علل مرگ (گرگ، رأی، قاتل، …): از پیام‌های عمومی مرگ نقش استفاده شود؛ متن علامت‌خوانی فقط برای shekar.
