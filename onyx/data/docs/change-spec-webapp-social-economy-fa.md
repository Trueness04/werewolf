# سند تغییرات محصول — انتقال اقتصاد/پروفایل به وب‌اپ + لایه سوشال (X/Twitter)

**وضعیت:** پیشنهاد محصولی — **غیرهم‌ارز PHP** (`product-new`)  
**نوع سند:** مشخصات تغییر (Change Spec)؛ بدون پیاده‌سازی کد  
**محدودیت:** بدون PHP / Python / React / Lang؛ بدون mock HTML یا بلوک کد پیاده‌سازی  
**تاریخ:** ۲۰۲۶-۰۸-۰۳  

**منابع موجود (رفتار امروز / شکاف‌ها):**  
- `docs/economy-shop-challenge-fa.md` — اقتصاد، شاپ، سکه، چالش، مجیک، آرایشی  
- `docs/economy-gaps-and-stubs-fa.md` — stubها و بک‌لاگ P0/P1  
- `docs/acceptance-backlog-mirror-fix-fa.md` — موارد undecided اقتصاد + ردیف‌های `product-new`

## ۰. خلاصهٔ محصول (یک‌بند)

کاربر می‌خواهد سامانه‌های **غیرگیم‌پلی هسته** (اقتصاد، فروشگاه، سکه، چالش، پروفایل) را به **Web App** شبیه X ببرد: پروفایل با آمار/سکهٔ عمومی و پست، **آیکون از کتابخانهٔ بازی** (هر رنک + هر مدال)، فید + دنبال‌کردن، گزارش پست، ویرایش/حذف مثل X. صفحهٔ **لیست رنک**؛ نفرات ۱–۳ **خاندان سلطنتی اونیکس**؛ نفر اول **حکمران** و نامش در اعلان رنک‌آپ بات. چالش فقط وب؛ بت حذف؛ شارژ ریالی تا قیمت‌گذاری و درگاه بانک ساخته نمی‌شود. گیم‌پلی ورولف در بات می‌ماند.

## ۱. تحلیل — امروز در PHP/بات در برابر هدف وب‌اپ

### ۱.۱ آنچه امروز در بات/PHP هست (غیرگیم‌پلی هسته)

| سامانه | محل مستند | وضعیت رفتاری کوتاه |
|--------|-----------|---------------------|
| سکه (`Players.credit`) | economy-shop §۲ | موجودی زنده؛ فرمان‌های `/mycoin`، `/sendcoin`، ادمین؛ مسیرهای رایگان عمداً خاموش |
| فروشگاه | §۳ | خرید جادو/اموجی/لقب/XP/نقش دزد — نیمه‌زنده |
| شارژ ریالی / دونیت | §۴ | P0 شکسته (توکن خالی، لینک نامرتب، verify خارج ریپو) |
| چالش گروهی | §۵ | UI/Lang زنده؛ handler استارت و insert سشن **غایب/شکسته** |
| مجیک در بازی | §۶ | خرید+اثر سه جادو؛ Sear مرده — **مصرف داخل سشن بازی** به هسته نزدیک است |
| اموجی / لقب / مدال زمان | §۷ | آرایشی در جوین/نام نمایشی |
| VIP / account | §۹ | ارتقا ماهانه در PV |
| دستاورد | §۱۰.۱ | آنلاک از پایان/گیم‌پلی؛ نمایش `/achievement` عملاً خالی |
| Hero / لیگ / تورنمنت | §۱۰، §۵.۳ | نیمه‌کاره یا جدا |
| ~~مود `coin`~~ | §۱۰.۳ | **حذف محصولی پذیرفته** (MF-60) — فقط مود؛ نه کیف پول |

پروفایل «سوشال» به‌معنای فید/پست/لایک در PHP **وجود ندارد**. آنچه نزدیک پروفایل است: فیلدهای بازیکن (سکه، XP/`Site_*`، VIP، اموجی، لقب، آمار بازی، مدال زمان، دستاوردهای Mongo).

### ۱.۲ آنچه در هستهٔ بات می‌ماند (ورولف)

| می‌ماند در بات | دلیل |
|----------------|------|
| لابی جوین، نقش‌دهی، شب، روز، رأی، لینچ | گیم‌پلی هسته |
| پیام‌های فاز و کیبورد نقش | تجربهٔ گروهی تلگرام |
| اثر مجیک **داخل سشن** (پس از خرید) | وابسته به Handler/Cron بازی — نقطهٔ تماس اقتصاد→هسته |
| دزد و مصرف سکهٔ درون‌بازی دزد | **حذف نقش دزد** — دیگر نقطهٔ تماس نیست |
| دستورات ادمین گروه / شروع بازی / kill / extend | عملیات سشن |
| اعلان آنلاک دستاورد در PV پس از بازی (اختیاری نگه/کوتاه) | سیگنال لحظه‌ای؛ جزئیات در وب |

### ۱.۳ آنچه به وب‌اپ منتقل می‌شود (غیرگیم‌پلی)

| انتقال به وب‌اپ | نگاشت به سند فعلی |
|-----------------|-------------------|
| اقتصاد / کیف پول / نمایش موجودی | economy-shop §۲ |
| فروشگاه (کاتالوگ خرج سکه) | §۳ |
| شارژ / دونیت (UI خرید) | §۴ — پس از حل gaps پرداخت |
| چالش (محصول بازسازی‌شده — **فقط وب**) | §۵ + gaps G-CH* |
| پروفایل کاربری سوشال | **جدید** + دادهٔ وضعیت بازی از Players/آمار |
| آیکون دستاورد/رنک روی پروفایل | §۱۰.۱ + کپی آینده از achievements-endstats-copy-* |
| News Feed + دنبال‌کردن | **جدید** — هر دو قفل‌شده (§۷) |

### ۱.۴ نتیجه‌گیری تحلیلی

بات امروز هم **موتور بازی** است هم **منوی متای شلوغ و نیمه‌مرده**. انتقال متا به وب‌اپ دو کار می‌کند: (۱) بات را به هستهٔ ورولف نزدیک می‌کند؛ (۲) برای پروفایل و فید اجتماعی سطحی می‌سازد که در تلگرام قابل تقلید تمیز نیست. این **parity PHP نیست** — بازطراحی محصولی است؛ stubهای اقتصاد باید قبل یا هم‌زمان با انتقال، **تصمیم پیاده/حذف/بازطراحی وب** بگیرند (نه mirror کور).

## ۲. محدودهٔ انتقال — نگاشت سامانه‌ها و شکاف‌ها

### ۲.۱ نگاشت سامانه → وب‌اپ در برابر بات

| حوزه | وب‌اپ (هدف) | بات پس از انتقال (حداقل) |
|------|-------------|---------------------------|
| موجودی سکه | نمایش کامل در وب؛ **انتقال سکه بین بازیکن‌ها بله** | در بات **عدد موجودی نمایش داده شود** (+ مسیر به وب) |
| شاپ | مرور/خرید کامل UI | حذف منوی شاپ از هسته یا redirect |
| شارژ ریالی | **فعلاً ساخته نمی‌شود** تا قیمت‌گذاری و تأیید درگاه بانک | بدون وعدهٔ شارژ در بات |
| چالش | خانهٔ کامل چالش — **فقط وب** | **هیچ فرمان چالشی در بات نماند** |
| پروفایل | هدر + آمار/سکهٔ عمومی + پست + آیکون بازی | بدون پروفایل سوشال |
| فید خبری + Follow | لندینگ پیش‌فرض؛ بدون پیام خصوصی | ندارد |
| لیست رنک / خاندان سلطنتی | صفحهٔ لیست رنک‌ها؛ رتبهٔ ۱–۳ سلطنتی | اعلان رنک‌آپ با نام **حکمران** (نفر اول) |
| مجیک | خرید در وب؛ استفاده در بات | پنل UseMajik در بازی |
| شرط‌بندی اسب / بت | **خارج — حذف محصول** (MF-14) | حذف؛ به وب‌اپ مربوط نیست |

### ۲.۲ stub / gaps که باید قبل از شیپ وب حل یا بازطراحی شوند

مرجع کامل: `docs/economy-gaps-and-stubs-fa.md`. موارد بحرانی برای انتقال:

| ID | موضوع | اثر روی وب‌اپ |
|----|--------|----------------|
| G-CH1…3 / MF-33…35 | چالش بدون backend واقعی | چالش «فقط وب» باید از صفر طراحی شود؛ کپی PHP ممکن نیست |
| G-PAY1…3 / MF-37…39 | پرداخت | **قفل ۲۰۲۶-۰۸-۰۵:** UI شارژ + قیمت‌گذاری **ساخته می‌شود** (بدون محصول کامل بانک درگاه نمی‌دهد)؛ کلید/verify واقعی پس از تأیید درگاه |
| G-FREE1/2 / MF-40 | فرمان سکه‌رایگان مرده | **حذف** — ربطی به مود `coin` نداشت |
| G-ACH2 / MF-44 | نمایش دستاورد خالی | **fix کامل** — نمایش در وب (+ بات در صورت ماندن دستور) |
| G-LAQ1/2، G-XP1، … | ناهماهنگی قیمت/متن | کاتالوگ وب یک قیمت واحد تعریف کند |
| G-TX / MF-51 | نبود ledger | برای وب + همگام‌سازی بات، ledger یا قرارداد sync صریح لازم است |
| MF-41…43، ۴۸…۵۷ | Sear، Hero، آیتم‌های Lang، … | **تکمیل نه حذف** — خرید وب / اثر بات طبق قرارداد مجیک |

**یادآوری:** موارد undecided اقتصاد در `acceptance-backlog-mirror-fix-fa.md` §۳.۵ و §۴ همچنان بلاک‌کنندهٔ اعلام «parity اقتصاد»اند؛ انتقال وب‌اپ آن‌ها را **لغو نمی‌کند** — یا تصمیم کاربر می‌گیرد یا در وب به‌عنوان محصول‌جدید بازتعریف می‌شوند و از acceptance هم‌ارزی PHP خارج می‌مانند (`product-new`).

### ۲.۳ آنچه عمداً از انتقال کامل خارج است (نقطهٔ تماس)

- اعمال مجیک در سشن، هر فلگ Redis بازی.  
- ~~دزد~~ **حذف محصولی**.  
- آنلاک دستاورد از رویداد گیم‌پلی (نوشتن `achievement_player`) می‌تواند از موتور بازی بماند؛ **نمایش و زینت پروفایل** در وب.  
- ارشد رنک / پنل کنترل بازی (`change-spec-meta-rank-role-links-fa.md`) — change-spec جدا؛ اگر ارشد به رنک وابسته است، رنک در وب نمایش داده می‌شود ولی پنل کنترل همچنان PV/بات است مگر بعداً تصمیم خلاف.

## ۳. پروفایل سوشال

### ۳.۱ هدف تجربه

پروفایل شبیه شبکهٔ اجتماعی: هویت بازیکن، وضعیت/آمار/سکه (عمومی)، دیوار پست مثل X، و **آیکون‌های کتابخانهٔ بازی** — نه عکس تزئینی دلخواه. برای **هر رنک** یک آیکون نمونه و برای **هر مدال** یک آیکون؛ روی پروفایل جلوه می‌دهند.

### ۳.۲ موجودیت‌های پیشنهادی (مفهومی)

| موجودیت | نقش | یادداشت |
|---------|-----|---------|
| **User** | هویت وب = بازیکن بازی (همان user_id تلگرام یا پیوند حساب) | فیلدهای وضعیت: رنک/XP، سکه (خواندنی از منبع حقیقت)، VIP، آمار برد/بازی، اموجی/لقب فعال اگر هنوز محصول بماند |
| **Post** | محتوای کاربر روی پروفایل و فید | متن؛ محدودیت طول به پارادایم X نزدیک |
| **Media** | پیوست تصویر (و بعداً در صورت نیاز انواع دیگر) | به Post وابسته؛ قوانین حجم/فرمت باز |
| **Like** | واکنش روی Post (و در صورت تصمیم، روی بعضی Activity) | یک کاربر یک لایک به‌ازای هدف |
| **Comment** | پاسخ متنی به Post | نخی ساده در MVP؛ تو‌در‌تو اختیاری/بعدی |
| **Follow** | گراف دنبال‌کردن | **قفل:** فید سراسری + دنبال‌کردن |
| **AchievementIcon** | آیکون کتابخانهٔ بازی روی پروفایل | **قفل:** یک نمونه per رنک + یک per مدال |
| **FeedItem** | آیتم تایم‌لاین | §۴ |
| **Report** | گزارش پست/محتوا | **قفل:** کاربران ریپورت می‌کنند |
| **RankStanding** | جایگاه در لیست رنک سراسری | §۴ب — خاندان سلطنتی |

پیام خصوصی دو نفره در وب‌اپ: **ساخته نمی‌شود** (قفل کاربر).

### ۳.۳ وضعیت بازی روی پروفایل (هدر)

حداقل سیگنال‌های قابل‌نمایش (خواندن از دادهٔ بازیکن/آمار؛ نه گیم‌پلی زندهٔ سشن مگر «الان در بازی» به‌عنوان badge اختیاری):

- نام نمایشی / لقب / آواتار  
- رنک و پیشرفت به‌سمت رنک بعد  
- خلاصه آمار (تعداد بازی، برد، …)  
- موجودی سکه و آمار بازی (**عمومی — دیگران می‌بینند**)  
- ردیف آیکون‌های رنک و مدال از کتابخانهٔ بازی  

منبع متن مدال/دستاورد برای UI آینده: `achievements-endstats-copy-full-fa.md` — **فقط ارجاع محتوا**؛ این change-spec کپی را بازنویسی نمی‌کند.

### ۳.۴ آیکون‌ها — قواعد نمایش (قفل‌شده)

1. منبع = **کتابخانهٔ آیکون‌های بازی** (نه گالری عکس تزئینی کاربر برای این بخش).  
2. **به‌ازای هر رنک** یک آیکون نمونهٔ متناظر.  
3. **به‌ازای هر مدال** یک آیکون متناظر.  
4. آنلاک‌شده روی پروفایل به‌صورت ردیف زینت (زیر هدر / کنار هویت) — نه داشبورد کارتی شلوغ.  
5. متن عنوان/توضیح مدال می‌تواند از `achievements-endstats-copy-full-fa.md` بیاید.

### ۳.۵ پست کاربر (قفل‌شده — قابلیت‌های نسبی X)

- پست متن/عکس روی پروفایل خود؛ همان پست در فید.  
- **ویرایش** پست توسط نویسنده.  
- **حذف** پست توسط نویسنده.  
- **حذف کامنت** دیگران توسط صاحب پست.  
- **گزارش (ریپورت)** توسط کاربران برای محتوای ممنوع (لو نقش زنده، توهین، محتوای جنسی، …).

## ۴. News Feed

### ۴.۱ نقش صفحه

**لندینگ پیش‌فرض** پس از ورود به وب‌اپ (home). ترکیب اخبار فعالیت اعضا + پست‌های کاربر. از فید می‌توان به پروفایل دیگران رفت.

### ۴.۲ انواع آیتم فید (حداقلی)

| نوع (`feed_item_type`) | منبع رویداد | محتوای خلاصه |
|------------------------|-------------|--------------|
| `rank_up` | تغییر رنک/سطح بازیکن | «X به رنک Y رسید» |
| `medal` | مدال زمان یا مدال تعریف‌شدهٔ محصول | «X مدال … گرفت» |
| `achievement` | آنلاک `achievement_player` یا آیکون رنک | «X دستاورد … را باز کرد» |
| `user_post` | Post جدید | متن/پیش‌نمایش مدیا + لینک پروفایل |
| `shop_showcase` (اختیاری بعدی) | خرید نادر/آیتم ویژه | فقط اگر محصول بخواهد فید شلوغ نشود |
| `challenge_event` (اختیاری) | شروع/پایان چالش وب | وابسته به تصمیم چالش کاملاً وب |

رویدادهای صرفاً درون‌دست (کشتن شب، رأی) **وارد فید عمومی نشوند**.

### ۴.۳ تعاملات

| عمل | روی چه | رفتار |
|-----|--------|--------|
| پسند | پست کاربر | مثل X |
| نظر | پست کاربر | مثل X؛ صاحب پست می‌تواند نظر را پاک کند |
| گزارش | پست (و در صورت نیاز نظر) | کاربران ریپورت می‌کنند |
| دنبال | کاربر | Follow / Unfollow |
| بازدید پروفایل | از فید یا لیست رنک | رفتن به پروفایل |
| نوشتن پست | کامپوز | مثل X |

### ۴.۴ ترتیب

زمان نزولی + صفحه‌بندی؛ فید سراسری پیش‌فرض؛ فیلتر دنبال‌شوندگان هم هست.

## ۴ب. لیست رنک و خاندان سلطنتی اونیکس (قفل‌شده)

### ۴ب.۱ صفحهٔ لیست رنک در وب‌اپ

یک بخش جدا در وب‌اپ بازیکنان را **به‌صورت لیست رنک** نشان می‌دهد (مرتب‌سازی بر اساس همان رنک/XP که در بازی و ارشد جلسه استفاده می‌شود — قفل: رنک وب = رنک ارشد).

### ۴ب.۲ خاندان سلطنتی

| رتبه در لیست | عنوان محصولی |
|--------------|----------------|
| نفر اول | **حکمران** اونیکس |
| نفر دوم و سوم | همراهان **خاندان سلطنتی اونیکس** (سه نفر اول با هم سلطنتی‌اند؛ اول = حکمران) |

### ۴ب.۳ اعلان در بات (قرارداد PHP + هدف محصول)

در Lang کلید `NewLevel` الگوی «به دستور … اونیکس 👑 (نام) از درجه {0} به {1}» دارد و جای خالی نام برای **حکمران** است.

**وضعیت امروز PHP (نقص):**  
- در `HL.php` هنگام رنک‌آپ، `{2}` با `ConvertName(1609838807, …)` **هاردکد** پر می‌شود، نه با نفر اول واقعی لیست.  
- در بعضی فایل‌های `main_fa.ini` خود متن `NewLevel` هم نام ثابت دارد و با placeholder هم‌خوان نیست.

**هدف محصولی (قفل):**  
اعلان‌هایی مثل رنک‌آپ در بات باید با **نام حکمران فعلی** (نفر اول لیست رنک) بروند — نه شناسهٔ هاردکد. وقتی حکمران عوض شود، اعلان‌های بعدی نام جدید را می‌گیرند.

### ۴ب.۴ پیشنهاد تکمیل (اگر کاربر خلاف نگوید)

- عنوان جدا برای نفر ۲ و ۳ **لازم نیست**.  
- تاج/بج روی پروفایل نفرات ۱–۳ در وب توصیه می‌شود.

## ۵. جهت طراحی UX (پارادایم X)

الزام جهت (نه mock):

- خانه = فید عمودی؛ پروفایل = هدر + آیکون‌ها + تایم‌لاین پست.  
- کامپوز، لایک، کامنت، ویرایش/حذف/ریپورت مثل قابلیت‌های نسبی X.  
- صفحهٔ لیست رنک و سلطنت جدا از فید، ولی لینک‌پذیر از فید/پروفایل.  
- فروشگاه/کیف پول مسیر جدا — نه داشبورد شلوغ روی صفحهٔ اول.  
- بدون پیام خصوصی.

صریحاً خارج: بت/شرط‌بندی؛ گرید ویجت اقتصاد روی home؛ شارژ ریالی تا درگاه و قیمت‌گذاری آماده شود.

## ۷. تصمیم‌های قفل‌شده و باقی‌مانده

### ۷.۰ قفل‌شده (پاسخ کاربر — زبان ساده)

| موضوع | تصمیم |
|--------|--------|
| دنبال‌کردن + فید | هر دو |
| چالش | فقط وب‌اپ |
| پیام خصوصی | ساخته نمی‌شود |
| موجودی در بات | **نمایش بده** (عدد) |
| جادو | خرید از وب‌اپ؛ استفاده در بات |
| سکه/آمار روی پروفایل | **دیگران باید ببینند** (عمومی) |
| آیکون پروفایل | کتابخانهٔ آیکون بازی؛ هر رنک یک نمونه؛ هر مدال یک آیکون — **عکس تزئینی جدا نیست** |
| شارژ پول واقعی | **ساخته می‌شود** (UI + بسته‌های قیمت‌دار) — تأیید درگاه بانک بعد از دیدن محصول؛ کلید واقعی بعد از تأیید (قفل ۲۰۲۶-۰۸-۰۵) |
| بت / شرط‌بندی | **حذف**؛ به وب‌اپ مربوط نیست (قبلاً MF-14) |
| Hero / تورنمنت / لیگ | **تکمیل** — داخل محدودهٔ وب/اقتصاد؛ حذف نمی‌شود (قفل ۲۰۲۶-۰۸-۰۵) |
| جادوی Sear | **کامل** — خرید وب‌اپ؛ استفاده در پنل مجیک داخل بازی |
| پست ممنوع | کاربران **ریپورت** کنند |
| ویرایش/حذف پست | بله — مثل قابلیت‌های نسبی X |
| حذف کامنت توسط صاحب پست | بله |
| رنک وب = رنک ارشد بازی | بله |
| لیست رنک | صفحهٔ لیستی در وب |
| نفر ۱–۳ | خاندان سلطنتی اونیکس؛ نفر اول = حکمران؛ اعلان بات با نام حکمران |
| لقب جدا برای نفر ۲ و ۳ | **نیازی نیست** — فقط رتبه در لیست / برچسب خاندان |
| انتقال سکه بین بازیکن‌ها | **بله** — در وب‌اپ (و هم‌تراز با مسیر بات در صورت ماندن) |
| دستور سکه‌رایگان مرده (`/getfreecoin` و مشابه) | **حذف** — این مود سکه نبود؛ فرمان مردهٔ جدا بود |
| نقش دزد | **حذف** (تصمیم کاربر) |
| ورود به وب‌اپ | **تلگرام Web App** (ورود داخل تلگرام — نه فرم جداگانهٔ مبهم) |

### ۷.۱ هنوز باز

مورد باز معنادار برای وب‌اپ در این دور **نمانده** (جز جزئیات فنی پیاده‌سازی WebApp که خارج از تصمیم محصولی است).

**یادداشت شفاف‌سازی:** سؤال قبلی «سکه رایگان قدیمی» یعنی فرمان‌های مردهٔ `CM_FreeCoin` / `CM_GetCoin` بود، **نه** مود بازی `coin` (که قبلاً حذف شده) و **نه** نقش دزد.
