# گزارش ناقصی‌ها و نقص‌های PHP — مرجع بازنویسی پایتون

**منبع ممیزی:** `bot/vendor/phpcron/telegram-bot/src` (+ لایه تریگر `bot/Commands`)  
**تاریخ ممیزی:** ۲۰۲۶-۰۸-۰۳  
**قوانین:** بدون Notes_Mode؛ بدون دامپ کد؛ تمرکز روی رفتار مشاهده‌شده و تصمیم «mirror یا fix»  
**همراه:** `docs/sprint-10-commands-callbacks-fa.md`

شدت‌ها:

| شدت | معنی |
|-----|------|
| **blocker** | بازی را در مسیر اصلی می‌شکند یا حلقه بی‌نهایت/داده‌ی فاسد می‌سازد |
| **high** | منطق برد/نقش/فاز غلط یا مسیر مهم مرده |
| **medium** | باگ مرزی، نشت فلگ، وزن غلط، مسیر فرعی شکسته |
| **low** | کامنت اشتباه، stub بی‌اثر، بدهی مستند/DX |

برای هر مورد: **پایتون باید mirror کند یا عمداً fix؟** — توصیهٔ پیش‌فرض برای بازنویسی سالم در ستون آخر آمده است.

# الف) نقص‌های بحرانی مسیر بازی

## ۱. منافق در رأی — بدون return پس از پایان بازی

| فیلد | مقدار |
|------|--------|
| **شدت** | blocker |
| **کجا** | `VT.php` → مسیر لینچ وقتی `user_role == role_monafeq` (داخل حل رأی؛ فراخوانی `HL::GamedEnd('monafeq')`) |
| **رفتار مشاهده‌شده** | پس از مرگ منافق و `GamedEnd('monafeq')`، تابع **return نمی‌کند** و به شاخهٔ لینچ عادی می‌افتد: پیام `killed_user` دوباره، `UserDead` دوباره، ذخیرهٔ رأی دوباره. |
| **اثر روی پایتون** | **عمداً fix.** برد منافق باید فوری و با یک‌بار مرگ/پیام تمام شود. Mirror باعث دوباره‌کشی و وضعیت پایان دوبل می‌شود. |
| **اصلاح پیشنهادی** | بعد از `GamedEnd('monafeq')` حتماً خروج از تابع حل رأی؛ قفل `GameIsEnd` را قبل از هر اثر ثانویه چک کنید. |

## ۲. فرمول برد تیم سیاه — عملاً غیرممکن

| فیلد | مقدار |
|------|--------|
| **شدت** | high |
| **کجا** | `HL.php` → `CheckEndGame` (شرط `black`) |
| **رفتار مشاهده‌شده** | شرط شبیه «تعداد black بزرگ‌تر از (روستا + آتش‌نشان + **خود black** + منافق)» است. چون black در سمت راست هم جمع می‌شود، نابرابری برای تیم سیاه practically unreachable است مگر شمارش‌های عجیب/باگ شمارش. |
| **اثر روی پایتون** | **عمداً fix با سند تصمیم.** اگر هم‌ارزی باگ‌دار PHP لازم است، mirror و در تست صریح ثبت کنید که برد سیاه از این فرمول نمی‌آید. توصیه محصولی: black را از سمت راست حذف کنید (مقایسه با غیرسیاه‌ها). |
| **اصلاح پیشنهادی** | `black > (rosta + Firefighter + monafeq)` با wolf/vampire/ferqe صفر؛ هم‌راستا با الگوی Firefighter. |

## ۳. StopBlack / CheckBlack — وقفهٔ مرده

| فیلد | مقدار |
|------|--------|
| **شدت** | high |
| **کجا** | `HL.php` → `CheckBlack` (بدنه خالی)؛ خواندن فلگ `GamePl:StopBlack` در `CheckTimer` (night/vote) و گیت حذف Kill |
| **رفتار مشاهده‌شده** | هیچ `GetSet` برای `StopBlack` در کل سورس bot یافت نشد. `CheckBlack` خالی است. در نتیجه شاخه‌ای که قرار بود مثل `HunterKill` فاز را نگه دارد برای شوالیه سیاه، هرگز فعال نمی‌شود. |
| **اثر روی پایتون** | **Fix آگاهانه.** یا رفتار کامل BlackKnight interrupt را از VT/`BlackVoteNo` و نقش‌های سیاه بازطراحی کنید، یا صریحاً «بدون وقفه StopBlack» مستند کنید. Mirror کور یک API مرده می‌سازد. |
| **اصلاح پیشنهادی** | یا حذف کامل مسیر StopBlack، یا پیاده‌سازی: ست فلگ هنگام نیاز به انتخاب/تأخیر سیاه، resolve در `CheckBlack`، سپس پاک‌سازی فلگ. |

## ۴. MafiaUserRole — حلقه while وارونه + بدون تخصیص نقش

| فیلد | مقدار |
|------|--------|
| **شدت** | blocker (برای مود Mafia) |
| **کجا** | `join.php` → `MafiaUserRole`؛ `GameStarted` وقتی `gameModePlayer == Mafia` زود `return true` می‌کند |
| **رفتار مشاهده‌شده** | ۱) `do { … } while ($balance)` وقتی بالانس **موفق** است دوباره حلقه می‌زند (باید `while (!$balance)` باشد مثل `UserRole`). ۲) پس از خروج، نقش‌ها به بازیکن assign نمی‌شوند. ۳) `GameStarted` برای Mafia اصلاً `MafiaUserRole` را صدا نمی‌زند و مستقیم true برمی‌گرداند بدون رفتن به night از مسیر نقش‌دهی. |
| **اثر روی پایتون** | **Fix.** مود Mafia یا کامل پیاده شود یا از محصول حذف/غیرفعال شود. Mirror = بازی مافیا بدون نقش. |
| **اصلاح پیشنهادی** | هم‌تراز `UserRole`: حلقه تا بالانس، assign Mongo/Redis، سپس `ChangeGameStatus('night')`. |
